1. Background & Problem Statement

1.1 The Setting

We have a binary classification task:

LabelClassLabel ReliabilityProportion
0BogusHighly reliable~25%
1FraudNoisy (may contain mislabeled bogus)~75%

This is an asymmetric label noise problem: one class has trustworthy labels while the other contains errors. Some cases labeled "fraud" are actually bogus cases that were missed or mislabeled.

1.2 The Model: TabICL

TabICL is a pre-trained transformer for tabular data that performs in-context learning (ICL). Unlike traditional models:

  • It is frozen — no fine-tuning or gradient updates
  • It receives a support set (training examples) and a query set (samples to predict) in a single forward pass
  • Learning happens through attention over the support set, not weight updates
Key Implication

Since the model cannot be optimized, the only lever for improving performance is the support set itself. The quality and composition of the support set is the model's "training".

performance = f(label quality, support-set composition)

1.3 The Problem

Given:

  • P = reliable positives (bogus, ~2,500 in training)
  • N = noisy negatives (fraud, ~7,500 in training, some mislabeled)
  • f(·) = frozen TabICL model

Goal: Construct an optimal support set that maximizes TabICL's ability to detect bogus cases, despite the noise in fraud labels.

2. Motivation

2.1 Why Not Just Use All Data?

TabICL has memory/compute constraints on support set size. With 150 features and T4 GPUs (16GB), practical support set size is ~1,000 samples. We must choose which 1,000 samples to include.

2.2 Why Not Random Sampling?

Random sampling from all fraud-labeled data includes mislabeled samples that confuse the model. If 10% of fraud labels are actually bogus, a random 500-sample fraud selection contains ~50 wrong labels — teaching the model incorrect patterns.

2.3 The Two-Stage Insight

The solution separates into two problems:

  1. Which fraud labels can we trust? (reliability scoring)
  2. Which trusted samples should teach the model? (support set selection)
EM Analogy: This resembles Expectation-Maximization.
E-step: Estimate which labels are reliable (using model predictions).
M-step: Optimize the support set (using reliable labels).
The model's predictions inform label trust, and label trust informs the model's input.

3. Core Algorithm

3.1 High-Level Flow

Stage A: Build K=20 random stratified support sets (size 500 each) | v Stage B: For each fraud sample in training set, run through all K support sets --> K-dimensional prediction vector per sample | v Stage C: Compute reliability scores from prediction vectors Threshold --> Reliable / Uncertain / Suspect | v Stage D: Construct optimized evaluation support set (1000 samples) = 500 bogus (diversity sampled) + 500 fraud (random from reliable set) | v Stage E: Evaluate on validation set (PR-AUC) If improved --> save as best, repeat from Stage B If converged --> stop

3.2 Critical Design Decision: Fixed Scoring Sets

Lesson learned: The 20 random support sets used for scoring (Stage B) must remain fixed across all iterations. Replacing them with "optimized" sets creates homogeneous predictions that destroy the diversity needed for reliable scoring. See Section 6 for details.

3.3 What Each Stage Does

CPrediction matrixReliability scores + classificationIdentify trustworthy fraud labels

4. Reliability Scoring in Detail

4.1 Prediction-Behavior Space

Since TabICL only returns probabilities (no internal embeddings), we define sample similarity through prediction behavior:

Prediction Vector

For each fraud sample xi, run it through K=20 different support sets:

vi = [P(fraud | S1), P(fraud | S2), ..., P(fraud | S20)]

Samples that behave similarly across diverse contexts are "prediction-behavior neighbors."

Intuition: A truly-fraud sample should be consistently classified as fraud regardless of which support set provides context. A mislabeled sample will be unstable — some support sets "recognize" it as bogus while others don't.

4.2 Five Scoring Components

ComponentSymbolFormulaWhat It Measures
Mean Probability μi mean(vi) How consistently the model says "fraud"
Stability σi std(vi) / 0.5 Prediction variance (lower = more stable)
Entropy Hi -μ log2(μ) - (1-μ) log2(1-μ) Model uncertainty (lower = more confident)
Neighborhood Agreement Ai fraction of k-NN with μ > 0.5 Do similar-behaving samples also look like fraud?
Density Di 1 / mean_distance_to_kNN Is this sample in a dense cluster? (normalized to [0,1])

4.3 Combined Reliability Score

ri = 0.30 · μi + 0.20 · (1 - σi) + 0.15 · (1 - Hi) + 0.20 · Ai + 0.15 · Di

Weight rationale:

  • μ (0.30): Strongest signal — if the model consistently says fraud, it likely is
  • 1-σ (0.20): Stability across different contexts indicates robust classification
  • A (0.20): Neighborhood consensus validates individual predictions
  • 1-H (0.15): Low entropy means the model isn't confused
  • D (0.15): Dense regions are more likely to have consistent labels

4.4 Neighbors in Prediction-Behavior Space

Neighbors are defined by cosine similarity on the K-dimensional prediction vectors:

sim(vi, vj) = (vi · vj) / (||vi|| · ||vj||)

Using k=15 nearest neighbors. This is computed via brute-force kNN on ~7,500 samples in 20 dimensions — essentially instant.

4.5 Classification Thresholds

CategoryConditionMeaning
Reliableri ≥ threshold (default 0.55)High confidence this is truly fraud
Uncertain0.35 ≤ ri < thresholdAmbiguous — could be either class
Suspectri < 0.35Likely mislabeled (actually bogus)

5. Support Set Construction

5.1 Composition (1000 total, balanced)

ComponentCountSourceSelection Method
Positives (bogus)500All bogus-labeled (trusted)K-Means diversity in feature space
Negatives (fraud)500Reliable fraud samplesRandom sampling

5.2 Why Balanced?

Even though the data is 75/25 fraud/bogus, the support set is 50/50. This gives TabICL equal representation of both classes in its context window, preventing it from defaulting to the majority class.

5.3 Positive Selection: Feature-Space Diversity

For the 500 bogus samples, we want representative coverage of the bogus distribution:

  1. Run KMeans(n_clusters=500) on all 2,500 bogus samples' features
  2. From each cluster, select the sample closest to the centroid

This ensures the support set covers the full bogus manifold rather than over-representing dense regions.

5.4 Negative Selection: Random from Reliable

For the 500 fraud samples, randomly sample from the reliable set (ri ≥ threshold).

Why random instead of diversity sampling? Random sampling naturally includes some near-boundary cases that teach TabICL where the decision surface is. KMeans diversity sampling selects "prototypical" fraud cases far from the boundary — easy examples that don't help discrimination.

5.5 Iteration: What Changes?

Across iterations, the reliability scores stay fixed (same random scoring sets). What changes:

  • Different random seed → different 500 random samples from the reliable pool
  • Each draw is evaluated on validation set
  • Best PR-AUC draw is kept

This is essentially a random search over support set compositions within the reliable pool.

6. Lessons Learned from Experiments

6.1 Problem: Optimized Scoring Sets Degrade Performance

What happened

Original design: replace the 20 random scoring sets with optimized ones each iteration.

Result: Iteration 2 always performed worse than iteration 1 (PR-AUC dropped 5-10%).

Root cause: "Optimized" support sets (all built from reliable negatives) were too similar to each other. When you probe a sample with 20 near-identical contexts, all predictions agree — not because the sample is reliable, but because the probes lack diversity. This made every sample look "reliable," destroying signal.

6.2 Problem: KMeans Diversity Selects Easy Negatives

What happened

KMeans centroids in prediction-behavior space are "prototypical" fraud cases — the most average, easy-to-classify examples. These are far from the decision boundary.

Result: The support set taught TabICL about obvious fraud, not about the subtle boundary between fraud and bogus. Performance was worse than random.

Fix: Random sampling from the reliable set naturally includes both easy and boundary cases.

6.3 Problem: Default Threshold Too High

What happened

With threshold=0.75, iteration 1 found 0 reliable samples. The scoring components don't all max out — especially density and agreement, which depend on the data distribution.

Fix: Lower to 0.55 (or use percentile-based thresholds instead of absolute values).

7. Future Enhancements

7.1 Adaptive Thresholds

Instead of fixed thresholds (0.55, 0.35), use percentile-based:

reliable = top 40% by score
suspect = bottom 20% by score
uncertain = middle 40%

This adapts to the actual score distribution regardless of the data.

7.2 Option C: Weighted Random Sampling

Instead of uniform random from the reliable set, sample with probability proportional to reliability score:

P(select xi) ∝ ri

Higher-reliability samples are more likely selected, but randomness ensures natural diversity. This is a soft version of thresholding.

7.3 Embedding-Space Neighbors

If TabICL exposes intermediate embeddings (e.g., via kv_cache="repr" mode), neighbors defined in embedding space would be more informative than prediction-behavior space. Embeddings capture semantic similarity beyond just classification output.

7.4 Dual-Neighborhood Scoring

Instead of one neighborhood, compute separate positive and negative neighborhoods:

score(x) = sim(x, Nfraud) / sim(x, Pbogus)

A truly-fraud sample should be much more similar to other fraud samples than to bogus samples. This ratio is often more informative than absolute distance alone.

7.5 Feature-Space + Prediction-Space Hybrid Neighbors

Combine both feature-level and prediction-level similarity:

combined_sim = α · simfeature + (1 - α) · simprediction

This captures both "what the sample looks like" and "how the model treats it."

7.6 Conformal Prediction for Uncertainty

Use conformal prediction to produce calibrated uncertainty sets. If a fraud sample's conformal set contains both classes, it's uncertain. This provides distribution-free guarantees on the uncertainty estimates.

7.7 Iterative Refinement with Fresh Random Sets

Instead of reusing the same 20 scoring sets, generate new random sets each iteration (still random, not optimized). This provides different prediction vectors each round, and reliability scores can be averaged across iterations for stability:

ri(final) = mean(ri(1), ri(2), ..., ri(T))

7.8 Active Learning Loop

Use suspect samples (likely mislabeled) as candidates for manual review. Each iteration:

  1. Flag top-50 suspect samples for human review
  2. Corrected labels enter the trusted positive pool
  3. Rebuild support set with expanded reliable data

This creates a human-in-the-loop system where each review cycle improves both label quality and model performance.

7.9 Multi-Objective Support Set Optimization

Optimize support set composition along multiple axes simultaneously:

  • Label purity: Minimize probability of including mislabeled samples
  • Feature coverage: Maximize representation of the data manifold
  • Boundary information: Include informative near-boundary examples
  • Class calibration: Ensure predicted probabilities are well-calibrated

7.10 Scaling to Large Datasets

For datasets with 100K+ samples:

  • Increase K (support sets for scoring) to 50-100 for more stable prediction vectors
  • Use approximate nearest neighbors (FAISS) instead of brute-force kNN
  • Distributed multi-server inference with sharded query data
  • Progressive filtering: first pass with K=5 to eliminate obvious suspects, then K=20 for the rest
